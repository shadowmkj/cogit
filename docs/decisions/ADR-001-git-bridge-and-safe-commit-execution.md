# ADR-001: Git Bridge Architecture and Safe Commit Execution

## Status
Accepted

## Date
2026-08-20

## Context
`cogit` must inspect staged Git changes and execute commits. Two architectural approaches were evaluated:
1. Linking against native `libgit2` via Rust bindings (`git2-rs`).
2. Invoking the system `git` CLI directly via `std::process::Command`.

Furthermore, when committing messages generated by LLMs, commit text can span multiple lines, contain quotes, punctuation, emojis, and backticks.

## Decision
1. Use `std::process::Command` to invoke system `git`.
2. Commit messages are written to a secure temporary file (`tempfile::NamedTempFile`) and executed using `git commit -F <file>`.

## Alternatives Considered

### `libgit2` (`git2-rs`)
- **Pros:** In-process C library bindings, avoids spawning external sub-processes.
- **Cons:**
  - Bypasses user-configured Git hooks (`pre-commit`, `commit-msg`).
  - Does not inherit user's GPG/SSH commit signing configuration automatically.
  - Requires linking against OpenSSL/libssh2 on diverse target platforms, increasing binary complexity and cross-compilation friction.
- **Rejected:** Preserving developers' existing pre-commit hooks and GPG signing workflows is a core requirement.

### Shell String Arguments (`git commit -m "..."`)
- **Pros:** Simple one-liner invocation.
- **Cons:** Multi-line strings, bash quote expansion, shell escaping bugs, and OS argument length limits create fragility.
- **Rejected:** Passing commit messages through temporary files (`-F`) eliminates all shell escaping risks.

## Consequences
- Requires `git` to be installed in the user's `PATH` (standard for developers).
- Full compatibility with pre-commit hooks, GPG keys, and local Git configuration.
- Safe, lossless handling of multi-line commit descriptions.
